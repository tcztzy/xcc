XCC

An agent-controlled C compiler.

XCC is a Python 3.11+ standard-library C11 compiler and, more importantly, an engineering specimen for keeping coding agents inside intended behavior with specs, tests, oracles, and negative boundaries.

01

The control model

XCC treats agent development as an engineering control problem. The repository tells agents what they may do, which evidence counts, and which shortcuts are forbidden.

Operating rules

AGENTS.md

CPython 3.11+ support, stdlib-only runtime, licensing, and handoff gates.

Behavior contract

SPEC.md + specs/

Goals, constraints, interfaces, invariants, tasks, and bug backprops.

Executable truth

Tests and oracles

clang, LLVM llc, executable return codes, diagnostics, and real builds.

02

Evidence over claims

A compiler patch is not accepted because it looks plausible. It has to pass local gates that prove both correctness and restraint.

03

Failure modes blocked

The project validates negative space too. Unsupported work should fail loudly instead of slipping through as accidental behavior.

Failure mode Repository control
Hidden fallback compiler Driver specs and tests reject fallback backends.
CPython-specific compiler hacks Specs require general C semantics and forbid path/file branches.
Unsupported input accepted by accident Negative tests and validation cases check rejection boundaries.
Unverified behavior change Minimal reproducers, oracle checks, lint, and type gates.

04

Compiler pipeline

The implementation stays compact enough to inspect while running against real-world C translation units.

.c preprocessor lexer parser sema target assembly

LLVM IR

Textual IR and object lowering through verified LLVM llc.

Darwin AArch64

Native assembly emitted directly for macOS ARM64 development.

Linux x86_64

Native ELF SysV assembly with project-agnostic driver behavior.

EVM

Freestanding contract bytecode for a focused C subset.
